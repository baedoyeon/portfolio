채널톡 배차 요청 자동 분류·전달 내이루리 · 2026

직접 운영하던 라이더 채널톡에 배차 문의가 급증해, 정형 문의는 AI가 자동으로 넘기고 사람은 긴급 건에 집중하도록 바꿨습니다. 배차 요청 전달 수기 5분을 30초로.

Process

문제에서 결과까지

문제 인식
  • 팀에서 운영하던 B마트 라이더 채널톡에 배차 요청 문의가 급증했습니다. 문의의 약 90%가 "배차 더 주세요" 같은 정형 문의였습니다.
  • 관리자가 22개 채널을 실시간으로 보며 배차방에 수기로 옮기느라 업무 시간의 70~80%를 모니터링에 썼고, 라이더는 요청 후 평균 5분(피크타임 최대 10분)을 기다려야 했습니다.
  • 반복 업무에 묻혀 지각·사고 보고처럼 안전과 직결된 메시지를 놓칠 위험이 있었습니다.
가설
정형 문의를 자동으로 가려내 배차방에 전달하면, 관리자가 사고·규제 같은 중요한 건에 집중할 수 있을 것이라고 봤습니다.
액션
  • 분류 기준을 현장에서 실제로 오가는 문장으로 정의해 프롬프트에 넣었습니다. 예시 없이 분류를 맡기지 않고, 실제 메시지 예시로 기준을 잡아 오분류를 줄였습니다 (아래 분류 기준 참고).
  • 판단이 애매한 메시지는 전부 Attention으로 분류해, 슬랙봇 연동으로 슬랙에 알림을 보내 사람이 확인하게 했습니다. 배차 요청을 놓치는 것보다 긴급 건을 자동으로 흘려보내는 것이 더 위험하다고 봤기 때문입니다.
  • 공식 API가 없는 채널이라 Playwright로 화면을 30초 간격으로 읽어 새 문의를 감지했습니다.
  • 라이더가 같은 요청을 연달아 보내 배차방이 도배되지 않도록, 라이더별 첫 요청 후 10분간 추가 요청은 게시하지 않게 SQLite로 제어했습니다.
검증
  • 1개 채널 실시간 모니터링 기준 PoC (라이더 348명, 일평균 메시지 2,685건)
  • 요청 감지부터 배차방 전달까지 걸린 시간을 수기 처리 시간과 비교
결과
  • 배차 요청 전달 리드타임 평균 5분 → 30초 이내
  • 정형 배차 요청의 수기 전달 단계를 시스템으로 대체
  • 개발팀 공식 API 연동 고도화를 위한 PRD 근거 마련
